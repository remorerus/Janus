# RE:Vision Windows Agent + Win SSH Agent

Windows-компонент для STUDIO PC. Windows Agent предоставляет защищённые команды управления ПК, приложениями и мультимедиа, а **Win SSH Agent** — отдельный каталог пользовательских SSH-команд с локальной веб-панелью. Это разные функции одного установочного пакета.

## Win SSH Agent — веб-панель

После установки открой непосредственно на STUDIO PC единый центр управления:

`http://127.0.0.1:47821/manager`

В верхней навигации доступны Windows Agent и SSH Agent. Старый адрес `/ssh-manager` оставлен для совместимости.

Панель SSH Agent показывает постоянный ID и отображаемое имя компьютера, состояние привязки RE:Vision и запросы на SSH-ключ. Имя можно менять без изменения постоянного ID и без повторной привязки. В каталоге команд доступны основная фраза и до 12 вариантов распознавания, а также типы: запуск EXE, закрытие и перезапуск приложения, запуск BAT, мультимедиа, горячие клавиши и управление окнами/фокусом. Каталог хранится отдельно от Windows Agent:

`%ProgramData%\WinSshAgent\commands.json`

Панель доступна только с loopback (самого компьютера). Она не открывает отдельный сетевой порт и не требует отдельного приложения/службы. Сам каталог команд не смешивается с командами Windows Agent.

## Как выполняется SSH-команда

1. Пользователь произносит фразу для RE:Vision.
2. Android-клиент подключается напрямую к Windows OpenSSH Server по SSH с ключом из Android Keystore.
3. Android вызывает установленный runner: `C:\Program Files\REVision Windows Agent\run-ssh-command.ps1`.
4. Runner передаёт фразу локальному Windows Agent на `127.0.0.1:47821`. Служба находит основную фразу или один из вариантов в `%ProgramData%\\WinSshAgent\\commands.json`.
5. Действия запуска, мультимедиа, горячих клавиш и окон выполняются в активной пользовательской сессии Windows тем же механизмом, что и команды Windows Agent. Для старых PowerShell/CMD-сценариев сохранена совместимость.
6. SSH-сессия завершается. Win SSH Agent не является фоновым SSH-сервером; постоянно открывать веб-панель не нужно.

Требуется включённый Windows OpenSSH Server и публичный ключ RE:Vision в `authorized_keys` именно того Windows-пользователя, под которым выполняется SSH-вход. Парольная SSH-аутентификация не используется: Android применяет приватный ключ, который остаётся в Android Keystore.

## Windows Agent и обнаружение в сети

В RE:Vision → Настройки → Windows Agent — STUDIO PC нажми «Найти компьютеры в локальной сети». Агент отвечает на UDP discovery-запрос на порту `47822` и сообщает только публичные метаданные: постоянный ID устройства, отображаемое имя, TCP-порт `47821` и список возможностей. Секреты, PIN и pairing code в discovery-пакет не попадают. После выбора найденного компьютера введи одноразовый код только при первом сопряжении. Секрет сопряжения сохраняется в Android EncryptedSharedPreferences.

Веб-панель Windows Agent также содержит раздел «Устройства в Wi-Fi». Он показывает устройства, которые отправляют в UDP-порт `47822` JSON-объявление с протоколом `revision-client-announcement-v1`. Формат объявления (без секретов и кодов сопряжения):
```json
{
  "protocol": "revision-client-announcement-v1",
  "deviceId": "постоянный-идентификатор-устройства",
  "name": "Rokid Glasses",
  "deviceType": "rokid",
  "appVersion": "версия-приложения"
}
```
Windows Agent сохраняет объявление в оперативном реестре и показывает IP отправителя и время последнего сигнала. Объявление не даёт доверия и не разрешает команды. Текущая Android/AIX-сборка ещё не отправляет этот пакет; отправитель будет добавлен на следующем этапе APK. После этого очки появятся в списке автоматически. В панели можно будет инициировать сопряжение выбранного ID; APK должен передать этот ID вместе с кодом, чтобы сервер привязал пару к правильному устройству.

В карточке «Привязка RE:Vision» добавлена команда «Забыть устройство»: она отзывает только текущий ключ Windows Agent ↔ RE:Vision и выпускает новый код. Каталоги команд, SSH-ключи и прочие настройки не затрагиваются. Физически инициировать повторное подключение со стороны Windows Agent без клиентского обработчика в APK невозможно; после забывания клиент должен запросить новое сопряжение.

Имя компьютера можно изменить в `/manager` в разделе «Имя компьютера в сети». Постоянный ID создаётся один раз и сохраняется в `%ProgramData%\\RevisionWindowsAgent\\agent.json`; смена IP или отображаемого имени его не меняет. Старые конфигурации дополняются ID и именем без сброса существующего pairing. UDP-ответчик работает внутри существующей службы Windows Agent и не создаёт отдельную службу или дополнительный исполняемый файл.

В локальной панели Windows Agent доступны дополнительные типы команд, которые пользователь сам создаёт в каталоге:

- **Управление мультимедиа** — действия AIMP: воспроизведение, пауза, Play/Pause, следующий/предыдущий трек, стоп, mute и громкость. Укажи путь к AIMP.exe; параметры проверяются по белому списку.
- **Горячие клавиши** — одиночные клавиши и сочетания из модификаторов CTRL, ALT, SHIFT, WIN и клавиш A–Z, 0–9, F1–F24, ESC, ENTER, TAB, SPACE, стрелок, HOME/END, DELETE и других стандартных клавиш. Примеры: F5, ENTER, CTRL+C, ALT+F4, WIN+D, CTRL+SHIFT+ESC. Примеры: CTRL+C, ALT+F4, WIN+D, CTRL+SHIFT+ESC.
- **Управление окнами и фокусом** — переключение на окно по имени процесса или части заголовка, сворачивание, разворачивание, восстановление, закрытие, следующее/предыдущее окно. Примеры процесса: chrome, explorer, aimp; для навигации между окнами есть Alt+Tab и Alt+Shift+Tab.

Горячие клавиши и управление окнами выполняются в активной пользовательской сессии Windows, а не в изолированной сессии службы. Произвольный PowerShell/CMD-код из этих типов не принимается.

Голосовые действия AIUI:
- `windows_status`
- `windows_lock`
- `windows_shutdown`
- `windows_restart`
- `windows_cancel_shutdown`
- `windows_launch` — команды из каталога Windows Agent; допускается удаление слова пробуждения «Ревижн» и безопасная коррекция одной ошибочной буквы в словах фразы. Если несколько команд одинаково похожи, агент не выполняет ни одну и возвращает неоднозначность.
- `windows_ssh_launch` — команда из каталога Win SSH Agent по точной фразе.

## Установка

GitHub Actions собирает self-contained ZIP для Windows x64. Распакуй архив, открой PowerShell от имени администратора и запусти `install-agent.ps1`. Установщик создаёт службу Windows Agent, настраивает отдельные каталоги данных и устанавливает SSH runner. Win SSH Agent использует тот же локальный HTTP-хост и порт 47821; каталог SSH-команд остаётся отдельным, но открывается из единого центра управления.

Для Windows OpenSSH установи публичный ключ RE:Vision на STUDIO PC. На странице настроек устройства в RE:Vision сгенерируй SSH-ключ и скопируй только публичную часть. На STUDIO выполни от имени администратора:

```powershell
.\install-ssh-public-key.ps1 -PublicKey 'PASTE_THE_PUBLIC_KEY_HERE'
```

Скрипт записывает публичный ключ в системный файл OpenSSH для администраторской учётной записи. Никогда не копируй приватный ключ с Android.

## Протокол Windows Agent

- `GET /v1/status`
- `POST /v1/pair`
- `POST /v1/command/lock`
- `POST /v1/command/shutdown`
- `POST /v1/command/restart`
- `POST /v1/command/cancel-shutdown`
- `POST /v1/command/execute`
- `POST /v1/unpair`

## Безопасность

Панель Win SSH Agent доступна только локально через loopback. SSH-выполнение идёт по OpenSSH с проверкой host key и ключевой аутентификацией; пароль не передаётся. Команды каталога содержат исполняемый код и запускаются с правами SSH-пользователя — сохраняй только доверенные команды.

Windows Agent использует HTTP без TLS и предназначен только для доверенной частной сети. Не открывай TCP 47821 и UDP 47822 в Интернет и не используй публичные Wi-Fi сети для сопряжения.


## Мультимедийные команды

Панель Windows Agent содержит тип «Управление мультимедиа». Для AIMP укажи `C:\Program Files\AIMP\AIMP.exe` и выбери действие из списка. Команды отправляются через штатные аргументы AIMP; допустимые параметры проверяются агентом перед запуском.
